# 科研实验方法论：从问题到可信证据

> 整理日期：2026-10-13  
> 用途：跨研究方向复用的工作指南，适用于计算与机器学习实验；其他方向可按领域惯例调整。  
> 边界：总结研究方法与工作习惯，不保留原项目的模型排名、性能结论，不要求继续原项目实验。

## 1. 核心原则：实验用于减少不确定性

科研不是不断增加实验、模块和分数，而是不断减少影响决策的关键不确定性。

> 一次实验最重要的问题：结果出来后，我会因此改变什么判断或行动？

如果无论结果怎样都会继续原方案，这次实验可能只是增加工作量，而没有帮助决策。

| 不确定性 | 核心问题 | 优先方法 |
| --- | --- | --- |
| 问题 | 困难是否真实存在、值得解决？ | 数据观察、失败案例、文献和需求分析 |
| 机制 | 为什么失败，什么干预可能有效？ | 最小对照、干预、机制诊断 |
| 实现 | 程序是否真正执行了预期方法？ | 单元测试、运行时审计、小样本验证 |
| 效果 | 改善是否稳定、泛化且值得成本？ | 完整实验、重复实验、独立评估 |

### 工作规则

1. 先识别当前最关键的不确定性，再选择实验。
2. 不用增加架构复杂度替代机制验证。
3. 不用工程测试通过替代效果证明。
4. 不用一次最好结果替代稳定性确认。
5. 允许结果为“仍不确定”，不要强行解释成成功或失败。

## 2. 选题：从真实问题出发

### 2.1 先观察困难，再选择技术

不推荐的起点：

> 把某种流行技术加入某个任务。

更好的起点：

> 现有方法在某类条件下出现可重复的错误，哪些原因可能解释它？

启动研究前，应明确：

- 谁或什么场景需要解决这个问题？
- 现有方法具体在哪里失败？失败频率和代价如何？
- 失败是方法能力不足，还是数据、标注、评价或实现问题？
- 已有研究如何解决它，仍留下什么缺口？
- 即使方法成功，能否回答一个有意义的问题？

### 2.2 先建立可信、简单的参照

参照方法不是陪衬，而是研究的测量工具。

先确认：

- 数据、标签和评价链路正确。
- 简单或公认方法能正常运行、达到合理表现。
- 常规的数据处理、输入设置或训练调整是否已解决主要困难。
- 复杂方法需要超越的实际参照是什么。

**一个可信的强参照，比很多条件不清楚的基线更有价值。**

参照结果明显异常时，应先审计，不急于解释为架构或理论局限。

## 3. 假设：把想法变成可证伪的预测

### 3.1 用四句话定义研究

1. **现象**：现有方法在哪些样本、条件或指标上失败？
2. **假设**：主要原因可能是什么？
3. **干预**：准备改变哪个因素？
4. **预测**：假设正确时，应该观察到什么变化？

示例：

> 方法在跨环境条件下波动明显；原因可能是表示依赖环境特征；增加针对环境变化的不变性约束；预期跨环境波动下降，而不仅是训练集分数提高。

### 3.2 同时写下否定条件

一个有用的假设，应允许实验不支持它。

提前说明：

- 什么结果支持假设？
- 什么结果削弱或否定假设？
- 什么结果仍无法区分不同解释？
- 如果被否定，下一步是检查实现、修改假设，还是停止该方向？

### 3.3 不把代理量当作真实概念

一致性、置信度、注意力、潜变量、聚类和辅助损失，都可能是有用的代理，但不自动等于真实可靠性、因果关系、物理量或语义结构。

需要区分：

- 指标定义了什么；
- 模型实际测量或预测了什么；
- 哪些解释需要额外证据。

**名称不能替代验证。预测稳定不等于正确，辅助任务学会不等于最终任务受益。**

## 4. 设计：让比较能够解释原因

### 4.1 区分实验目的

| 目的 | 问题 | 注意事项 |
| --- | --- | --- |
| 效果比较 | 哪个系统在给定条件下更好？ | 明确适用条件与评价协议 |
| 机制验证 | 哪个因素造成改善？ | 需要排除容量、预算等替代解释 |
| 效率比较 | 给定资源下哪个方案更值得用？ | 同时记录效果与实际资源成本 |

外部基线用于评价竞争力；同底座对照用于解释创新贡献。两者不能互相替代。

### 4.2 每轮只保留一个主要解释变量

这不是要求每次只能改一行代码，而是要求结果能够对应一个清楚的问题。

开发时允许多因素探索，但应标注为探索：

```text
探索可行性 → 找到候选方案 → 拆解主要因素 → 独立确认
```

不要把一整包同时变化的因素，直接归因于其中某个机制。

### 4.3 建立三种关键对照

1. **同底座对照**：保持主要实现和外部协议，移除待验证机制。
2. **简单替代对照**：用普通方法替代特殊设计。
3. **资源对照**：检查收益是否只是更多参数、训练、数据或外部预训练带来的。

不必每次运行全部对照，但每个重要主张都应有能够排除主要替代解释的证据。

### 4.4 区分干预诊断与重训消融

| 类型 | 回答什么 | 不回答什么 |
| --- | --- | --- |
| 同一模型关闭模块或扰动输入 | 已训练模型依赖什么？ | 删除后重新适应能达到什么水平？ |
| 删除模块后重新训练 | 该模块在训练系统中有何贡献？ | 单次差值是否稳定泛化？ |
| 重复实验与独立评估 | 结论是否稳定、适用边界如何？ | 是否已排除全部替代机制？ |

诊断可以筛选方向，但不能替代正式消融；正式消融也不自动证明普遍有效。

### 4.5 提前规定指标和取舍

记录：

- 主指标及选择模型的规则；
- 次要指标对应的研究问题；
- 不可接受的退化；
- 可接受的资源开销；
- 最小有意义收益及其依据。

多指标取舍是合法研究目标，但不能在结果出来后才换目标。

### 4.6 公平不等于所有超参数相同

公平比较需要条件透明、预算可解释，以及必要差异已披露。

- 同一比较组内固定数据划分、评价、选模型规则和相关外部条件。
- 不同方法可使用适合其收敛的设置，但调参机会与预算应合理可比。
- 机制实验尽量控制外部变量；架构效果实验允许合理适配，明确说明。
- 不同数据集可有不同协议，不强求无意义的跨数据集一致。
- 热启动记录继承预算与追加预算，不把追加成本当成总成本。
- 更新次数、数据曝光量、有效 batch 和实际耗时都值得记录。

注意：梯度累积不总等价于大 batch。BatchNorm、对比候选池和批内采样等可能依赖实际 micro-batch。

## 5. 执行：保证实际运行符合预期

### 5.1 记录实验身份

> 配置表达意图，运行时记录表达事实。

每次正式运行至少保存：

| 项目 | 内容 |
| --- | --- |
| 代码 | 提交号、未提交修改或代码快照 |
| 数据 | 版本、来源、划分和必要清单 |
| 初始化 | 实际加载来源；随机、预训练、热启动或恢复 |
| 参数 | 哪些参数可训练、是否进入优化器 |
| 训练 | 最终展开配置、精度、batch、更新次数、随机种子 |
| 资源 | 环境、设备、耗时、显存和并行条件 |
| 评价 | split、指标定义、选模型规则与实际权重 |
| 状态 | planned / running / completed / failed / interrupted |

实验身份应绑定具体运行，不只绑定模型名称或输出目录。

### 5.2 对关键状态设置启动核验

例如：

- 请求恢复时，确认 checkpoint 存在且兼容。
- 没有恢复权重时，明确报错，或明确进入正常的新训练路径。
- 打印实际加载的初始化来源，而不只打印预训练配置。
- 检查优化器覆盖了所有应训练参数，并排除意外重复。
- 确认训练和评估读取预期数据。

这些检查应尽量自动化，不依赖每次人工阅读长日志。

### 5.3 数据协议也是方法的一部分

裁剪、分辨率、视野、采样比例、归一化和标签转换，都可能显著影响结果。

改变输入协议时：

1. 先在固定方法上比较协议因素。
2. 选定并记录协议。
3. 再在该协议下比较方法。

涉及物理量时，同时记录单位、转换关系、评价容差和离散化规则。不能把输入条件改变的收益直接归于架构。

## 6. 验证：按层排除问题

| 层级 | 主要检查 | 通过后能说明什么 |
| --- | --- | --- |
| 数据 | 输入、标签、单位、划分、配对 | 读取和定义基本正确 |
| 数值 | 解析值、梯度、边界情况 | 关键计算符合预期 |
| 可学习性 | 小样本拟合、参数实际更新 | 路径具备学习能力 |
| 真实短程 | 成本、日志、保存、评价、恢复 | 生产链路基本可用 |
| 任务效果 | 同底座完整比较 | 在给定条件下观察到收益 |
| 结论确认 | 重复、独立评估、适用边界 | 重要结论获得更强支持 |

不要跳级，也不要过度扩大某层验证的含义：

- 梯度非零不证明有用。
- 小样本过拟合不证明泛化。
- 合成测试不证明真实训练成本。
- 单次完整实验不证明稳定性。

验证投入应与结论重要性和失败代价匹配，不要求所有探索都执行最昂贵的确认。

## 7. 分析：异常先审计，结论不越界

### 7.1 异常排查顺序

出现异常高分、低分或学习失败时，依次检查：

1. 数据、标签、划分和评价身份。
2. 实际初始化、恢复来源和训练预算。
3. 输入处理、参数更新及损失计算。
4. 运行是否完成，结果是否属于本次运行。
5. 最后分析方法机制和任务适配性。

排查也要有预算。实现已核验后，应允许假设被否定，避免无限寻找“肯定是代码问题”的解释。

### 7.2 分解误差，而不是只看总分

按研究需要分析：

- 样本类型、环境、难度或子群体；
- 类别、尺度和误差类型；
- 稳定性、校准、成本与失败率。

保留一组固定案例持续比较，避免只展示最有利样本。每项额外指标都应对应明确问题，不无限扩展指标。

### 7.3 区分证据与解释

| 等级 | 推荐表述 |
| --- | --- |
| 观察 | 本次运行观察到…… |
| 支持 | 受控比较支持这一解释…… |
| 确认 | 在这些独立条件下重复确认…… |
| 未确定 | 现有证据无法区分…… |

不要把相关性、注意力图或代理指标直接写成因果证明。多指标改善和退化应同时报告。

### 7.4 小收益需要匹配的稳定性证据

重要的小差值，应考虑：

- 训练随机性；
- 样本抽样波动；
- 模型选择与反复尝试造成的偏差；
- 样本相关性；
- 是否只挑最好种子、最好时点或最好指标。

Bootstrap 通常反映给定模型下的样本不确定性，不替代训练种子方差。相关样本应考虑按主体、场景、患者、设备或地理分组重采样。

### 7.5 开发与确认数据分开

- 开发、调参和继续/停止决策使用开发数据或验证集。
- 方法和规则锁定后，使用独立留出数据确认。
- 已反复影响开发的留出结果，不再视作独立确认。
- 同时检查空间、时间、主体与重复样本泄漏。

划分可复现不等于划分独立。应根据任务建立合理的分组与留出方式。

## 8. 效率：提高每次实验的信息价值

### 8.1 两阶段实验

| 阶段 | 可使用的简化 | 目的 |
| --- | --- | --- |
| 探索 | 短训练、少种子、小规模数据、廉价诊断 | 排优先级、排除明显无效方向 |
| 确认 | 固定协议、完整训练、必要对照与重复 | 支撑重要判断 |

不能把探索的低成本与确认的高可信度同时用于一个未经确认的主张。

### 8.2 省资源的正确顺序

1. 先减少重复和不能改变决策的实验。
2. 用廉价诊断缩小候选范围。
3. 对候选做完整可判别比较。
4. 把重复预算投入最重要或最不稳定的结论。
5. 确认核心效果后，再扩展全面实验矩阵。

不是省略必要对照，而是改变执行顺序。

### 8.3 性能优化依赖实测

- 在目标环境测量，不凭模块名称猜瓶颈。
- 测量完整工作负载，包括预处理、前后向、优化器与验证。
- 充分预热，注明共享设备或资源争用。
- 根据可承载量选择 micro-batch、精度和重计算。
- 优化后确认实验语义与数值行为没有非预期变化。

没有必要在机制尚未成立时反复做极致工程优化；但正式投入之前，要确认成本可承受。

## 9. 决策：管理复杂度与停止条件

### 9.1 增加复杂度前问四个问题

1. 它解决的是已观察到的问题吗？
2. 是否有更简单的替代？
3. 如何判断它解决了问题？
4. 没有收益时能否干净撤掉？

复杂度是成本，不是研究价值本身。每层复杂度应由前一层证据支持。

### 9.2 区分数值保护与学习限制

必要的数值处理与冻结、强正则、强门控、阶段训练等策略不是一回事。

不因“更安全”默认增加限制学习的机制。采用时说明问题证据，检查是否抑制有效学习，并通过适当对照评估。

### 9.3 提前规定继续、转向和停止

可参考的停止或转向条件：

- 多轮可判别实验仍不支持核心假设。
- 收益只存在于特定筛选条件，缺乏预期泛化。
- 简单替代达到类似效果。
- 资源需求超出可承受范围。
- 即使成功，也不能回答重要问题。

不用通用的固定次数或分数线替代领域判断。阈值应根据噪声、预算、目标和最小有意义收益制定。

> 决定是否继续，看下一步的信息价值，不看过去已投入多少。

负结果的价值是缩小不确定性。及时停止不等于否认过去的工作。

## 10. 工具：正确使用 AI 与自动化

### 10.1 适合交给工具的工作

- 查找实现和配置差异。
- 整理实际实验身份。
- 编写测试、审计和汇总脚本。
- 检查推导、单位和边界情况。
- 找出结果之间的矛盾。
- 提出区分不同解释的对照。

### 10.2 研究者应保留的判断

- 问题是否值得研究。
- 核心假设和指标是什么。
- 哪些代价可接受。
- 证据是否足够。
- 是否继续投入。

### 10.3 可复用的协作要求

```text
请分别列出事实、解释和待验证假设。
每项实验建议说明：它排除哪种不确定性，结果如何改变下一步决策。
优先提出最小可判别对照，不默认通过增加模块解决问题。
不要从测试通过推断效果，不要从单次涨分推断机制成立。
说明哪些内容实际核验过，哪些仍未知。
```

AI 可以加速实现，也会加速无证据的复杂化。代码生成速度不等于研究推进速度。

## 11. 记录：形成可追溯的研究资产

### 11.1 最小产物结构

以下是参考结构，可按工具链调整：

```text
research/
  questions.md              # 问题、假设与主要替代解释
  decisions.md              # 继续、转向、停止的理由
  protocols/                # 数据、训练与评价协议
  experiments/<run_id>/
    experiment_card.md      # 实验目的和预先约定
    identity.json           # 实际运行身份
    config_snapshot.*       # 最终展开配置
    logs/                   # 日志与状态
    metrics.json            # 绑定运行和评价身份
    analysis.md             # 事实、解释、未知与下一步
```

指标和分析文件应关联具体权重或产物，不能只关联模型目录。

### 11.2 方法学习记录

每轮重要工作结束后记五项：

1. 本来相信什么？
2. 哪条证据改变了判断？
3. 哪种实验最有效、哪种工作浪费了时间？
4. 下一次如何更早发现同类问题？
5. 哪些经验只适用于当前条件，不能外推？

### 11.3 项目结束不必补齐故事

项目结束时可保留：

- 可迁移的方法与工作习惯；
- 可复用工具；
- 已排除的解释及其条件；
- 明确仍未知的问题。

是否保存全部数据和权重，取决于未来用途、伦理合规及保存成本。积累方法论不要求把已停止项目补成完整论文。

## 12. 可复制模板

### 12.1 实验卡片

```markdown
# 实验：<名称>

- 运行 ID：
- 阶段：探索 / 确认
- 问题：具体要解决什么现象？
- 假设：认为原因是什么？
- 当前证据：为什么值得检验？
- 主要替代解释：
- 干预：改变哪个主要因素？
- 对照：如何排除其他解释？
- 固定条件与声明差异：
- 主指标与选模型规则：
- 次要指标与不可接受代价：
- 实际运行条件核验方式：
- 时间、资源与调参预算：
- 继续条件：
- 转向或停止条件：

## 结果
- 状态：planned / running / completed / failed / interrupted
- 运行产物与身份记录：
- 实际观察：
- 重要异常与协议偏离：
- 假设：被支持 / 被削弱或否定 / 仍不确定
- 尚不能得出的结论：
- 下一步决策及依据：
```

### 12.2 决策记录

```markdown
# 决策：<继续 / 转向 / 停止>

- 日期：
- 要决定的问题：
- 已核验的证据：
- 仍未知的因素：
- 可选行动及各自成本：
- 决定：
- 依据：
- 什么新证据会让这个决定改变：
```

### 12.3 结果分析四栏

| 已观察事实 | 可能解释 | 区分解释所需证据 | 下一步行动 |
| --- | --- | --- | --- |
| 填写实际结果，不加入归因 | 列出不止一种合理解释 | 选择最小可判别实验 | 继续、诊断、转向或停止 |

## 13. 分阶段检查表

### 13.1 立项前

- [ ] 问题具体，困难有观察依据。
- [ ] 已了解主要已有方法和剩余缺口。
- [ ] 数据、标签和评价能够支持研究目标。
- [ ] 有可信参照和可检验假设。
- [ ] 知道什么结果会削弱假设。
- [ ] 预算与初步停止条件明确。

### 13.2 正式运行前

- [ ] 实验卡片已写，结果会改变某项决策。
- [ ] 对照能排除主要替代解释。
- [ ] 代码、数据、划分与最终配置有记录。
- [ ] 初始化或恢复来源实际核验。
- [ ] 可训练参数、更新与精度路径已检查。
- [ ] 数据、数值、小样本和短程验证达到必要程度。
- [ ] 主指标、选模型规则和评估对象明确。
- [ ] 预算、输出位置和运行状态可追踪。

### 13.3 形成结论前

- [ ] 结果属于正确运行和正确产物。
- [ ] 未完成、失败和中断未混入完成结果。
- [ ] 已审计异常，未把工程错误解释成机制。
- [ ] 主次指标、代价和退化共同报告。
- [ ] 未挑选最好种子或混合不同权重的最优指标。
- [ ] 重要结论有匹配的重复或独立确认。
- [ ] 解释没有超出对照与统计证据。
- [ ] 适用条件和未知因素明确。

### 13.4 决定继续投入前

- [ ] 下一步能减少一个明确的不确定性。
- [ ] 新复杂度有证据支持，且考虑过简单替代。
- [ ] 投入基于未来信息价值，而不是沉没成本。
- [ ] 如果结果相反，愿意改变决策。

## 14. 一页速查

### 五条核心习惯

1. **先写可检验的问题，再选技术。**
2. **先核验实际实验条件，再解释结果。**
3. **让实验排除关键解释，不只产生一个分数。**
4. **用简单对照约束复杂度，用独立确认约束结论。**
5. **依据未来信息价值决定投入，不依据过去投入决定坚持。**

### 五类常见误判

| 容易误判 | 正确区分 |
| --- | --- |
| 总体领先就是核心机制有效 | 效果比较与机制归因不同 |
| 测试通过就是方法有效 | 实现正确与科学有效不同 |
| 指标下降就是架构不行 | 先排除数据、初始化与评价异常 |
| 追加训练很少就是总成本很低 | 继承预算与追加预算不同 |
| 留出分数一直用于开发仍算独立确认 | 开发反馈与独立确认不同 |

### 日常执行顺序

```text
观察问题
  → 写假设与否定条件
  → 建可信参照
  → 做最小可判别实验
  → 核验实际运行身份
  → 区分事实、解释与未知
  → 确认重要结论
  → 决定继续、转向或停止
```

**最有价值的科研产出之一，是知道什么不该继续做，以及为什么。**
